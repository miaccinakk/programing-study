1Что такое React

React — это библиотека (не фреймворк!) для построения пользовательских интерфейсов на JavaScript. Создана в Facebook (Meta).

🧩 Компонентный подход

UI разбивается на маленькие переиспользуемые кусочки — компоненты. Из них, как из кубиков LEGO, собирается вся страница.

🔁 Декларативность

Ты описываешь как должен выглядеть UI при определённом состоянии, а React сам обновляет экран. Не нужно вручную дёргать DOM.

🔑
Главная идея: UI = функция от состояния. UI = f(state). Меняется состояние → React перерисовывает то, что нужно.

2Принцип работы: Virtual DOM

React не трогает реальный DOM напрямую при каждом изменении — это медленно. Вместо этого он использует Virtual DOM.

01
State меняетсянапример, клик по кнопке
02
Новый Virtual DOMReact строит копию в памяти
03
Diffingсравнивает старую и новую версии
04
Обновлениеменяет в реальном DOM только разницу
✅
Благодаря этому React обновляет только изменившиеся элементы, а не всю страницу — отсюда высокая производительность.

3JSX — разметка внутри JS

JSX — это синтаксис, который позволяет писать HTML-подобную разметку прямо в JavaScript. Браузер его не понимает — его компилирует сборщик.

const name = "Аня";

// JSX выглядит как HTML, но это JavaScript
const element = <h1>Привет, {name}!</h1>;
⚠️
Что нужно запомнить про JSX:
  • Вместо class пишем className
  • JavaScript внутри разметки — в фигурных скобках { }
  • Компонент должен возвращать один родительский элемент (или <>...</> — фрагмент)
  • Все теги закрываются: <img />, <br />

4Компоненты

Современный React — это функциональные компоненты. Это просто функция, которая возвращает JSX. Имя обязательно с Большой буквы.

function Welcome() {
  return <h1>Привет 👋</h1>;
}

// использование как обычный HTML-тег
function App() {
  return (
    <div>
      <Welcome />
      <Welcome />
    </div>
  );
}
💡
Один компонент = один файл. Хорошая практика — маленькие компоненты, каждый отвечает за что-то одно.

5Props и State — самое важное 🎯

Это два способа работать с данными. Понимание разницы — база всего React.

PropsState
Данные снаружи, от родителя Данные внутри компонента
Только для чтения (нельзя менять) Можно менять через setState
Как аргументы функции Изменение → перерисовка компонента 
// PROPS — передаём данные вниз
function Hello({ name }) {
  return <p>Привет, {name}</p>;
}

<Hello name="Макс" />
// STATE — данные, что меняются
const [count, setCount] = useState(0);

<button onClick={() => setCount(count + 1)}>
  Кликов: {count}
</button>
🚫
Никогда не меняй state напрямую! count = 5 — так нельзя. Только через сеттер: setCount(5). Иначе React не узнает об изменении и не перерисует UI.

6Хуки (Hooks)

Хуки — это функции, которые «подключают» к компоненту возможности React (состояние, побочные эффекты и т.д.). Все начинаются со слова use.

useState — хранит состояние

Возвращает пару: текущее значение и функцию для его изменения.

const [value, setValue] = useState("");
setValue("новое значение"); // перерисует компонент

useEffect — побочные эффекты

Запросы к API, таймеры, подписки. Запускается после рендера. Массив зависимостей контролирует, когда он срабатывает.

useEffect(() => {
  console.log("запустится при изменении id");
}, [id]); // [] = только один раз при монтировании
⚠️
Пустой массив [] → эффект один раз. Нет массива → каждый рендер (осторожно, легко словить бесконечный цикл).

useContext — общие данные

Позволяет передавать данные глубоко вниз без «прокидывания» props через каждый уровень (тема, текущий юзер, язык).

const theme = useContext(ThemeContext);

useRef — ссылка без перерисовки

Хранит значение между рендерами и даёт прямой доступ к DOM-элементу. Изменение ref НЕ вызывает перерисовку.

const inputRef = useRef(null);
inputRef.current.focus();
📏
Правила хуков (важно на собесе!):
  • Вызывать только на верхнем уровне компонента — не в циклах, условиях или вложенных функциях.
  • Вызывать только внутри React-компонентов или своих кастомных хуков.

7Списки и условный рендер

// Списки — через map, обязателен key!
{users.map((user) => (
  <li key={user.id}>{user.name}</li>
))}

// Условие — тернарник или &&
{isLoggedIn ? <Profile /> : <Login />}
{hasError && <Error />}
🔑
key — уникальный идентификатор элемента списка. Помогает React понять, что изменилось. Не используй индекс массива как key, если список может меняться.

8События и формы

// События — camelCase, передаём функцию
<button onClick={handleClick}>Жми</button>

// Контролируемый input — значение живёт в state
const [text, setText] = useState("");

<input
  value={text}
  onChange={(e) => setText(e.target.value)}
/>
💡
Пиши onClick={handleClick}, а НЕ onClick={handleClick()} — второе вызовет функцию сразу при рендере.

9Сборка проекта

Браузер не понимает JSX и модули напрямую — их нужно «собрать» в обычный JS. Этим занимается сборщик (bundler).

Современный стандарт для старта. Очень быстрый dev-сервер и мгновенный hot-reload. 
npm create vite@latest my-app -- --template react
cd my-app
npm install
npm run dev
Фреймворк поверх React: роутинг, серверный рендеринг (SSR), API-роуты «из коробки». Часто используется в продакшене.
Babel — превращает JSX и новый JS в понятный браузерам код. Bundler (Vite/Webpack) — собирает все файлы и зависимости в оптимизированные бандлы, минифицирует, следит за изменениями.
КомандаЧто делает
npm installставит зависимости из package.json
npm run devзапускает локальный сервер разработки
npm run buildсобирает продакшн-версию

10Частые ошибки новичков

1️⃣
Мутируют state напрямую вместо setState / setX.
2️⃣
Забывают key в списках или ставят индекс массива.
3️⃣
Бесконечный цикл в useEffect из-за отсутствия массива зависимостей.
4️⃣
Вызывают хуки внутри условий или циклов.
5️⃣
Пишут onClick={fn()} вместо onClick={fn}.
